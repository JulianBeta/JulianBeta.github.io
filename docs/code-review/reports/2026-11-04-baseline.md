# Code review: Whole repository (baseline)

- **Date:** 2026-11-04
- **Scope:** Application code (`src/pages/**`, `src/layouts/**`, `src/components/**`, `src/data/**`, `src/content.config.ts`, `src/content/**`, `src/styles/**`), tests (`tests/**`, `playwright.config.ts`), `scripts/**`, `.github/workflows/**`, `astro.config.mjs`, `tsconfig.json`, `package.json`. - **Files reviewed:** 38 (5 of them tests)
- **Verdict:** The code is clean, well-structured and ships no JS. The main risks are test gaps (fonts, assets, the new Collaborations section, the committed CV PDFs), a broken language switch on the 404 page, and CI concurrency and permission settings.

## Summary
The codebase is small, consistent and easy to follow. Data lives in `src/data/`, routes are thin wrappers, and the test suite checks real behavior (PDF magic bytes, axe scans, link resolution, two-page print). The most important gaps are in what the tests cannot see. The font tests would still pass if the self-hosted fonts were removed. The link checker ignores every non-`<a>` asset (icons, `og:image`, collaboration screenshots). The committed CV PDFs are never checked against the current data. The newest feature, Development Collaborations, has no tests. On the 404 page, the language switch and `hreflang` point to a route that does not exist. The CI workflow can cancel a Pages deploy that is already running, and it gives pull-request runs Pages write permission. Fix the CI settings and the 404 switch first, then close the test gaps.

### R-01: Font tests cannot detect missing brand fonts
- **Severity:** Medium · **Category:** test quality
- **Location:** `tests/cv.spec.ts:30-37`, `tests/home.spec.ts:13-18`
- **Evidence:**
  ```ts
  expect(await page.evaluate(() => document.fonts.check('600 12pt "Oswald Variable"'))).toBe(true);
  expect(await page.evaluate(() => document.fonts.check('400 10pt "Nunito Variable"'))).toBe(true);
  await expect(page.locator('h2').first()).toHaveCSS('font-family', /Oswald/);
  ```
  ```ts
  await expect(page.getByRole('heading', { level: 1 })).toHaveCSS('font-family', /Oswald/);
  ```
- **Why it matters:** If no `@font-face` in the document matches the family, `FontFaceSet.check()` returns `true`. If the `@fontsource-variable/*` imports were dropped from `src/layouts/Base.astro:2-3` or `src/components/CV.astro:4-5`, or the family were renamed, `check()` would still return `true`. `toHaveCSS('font-family', /Oswald/)` only matches the declared stack string (`--display: 'Oswald Variable', 'Oswald', 'Arial Narrow', …` in `src/styles/global.css:23`), not the font actually rendered. Both tests would pass with fallback fonts, which is the regression they are meant to catch. The home test also never waits for fonts to load.
- **Suggested fix:** Assert that a matching face exists and is loaded, for example `await page.evaluate(async () => { await document.fonts.ready; return [...document.fonts].some(f => f.family.includes('Oswald') && f.status === 'loaded'); })`. Alternatively, check that `request.get()` of the Fontsource `woff2` URL returns 200. Reuse one helper for the home and CV tests.

### R-02: The 404 page's language switch and hreflang point to a page that does not exist
- **Severity:** Medium · **Category:** bug / i18n
- **Location:** `src/pages/404.astro:5`, `src/layouts/Base.astro:21-25`, `src/layouts/Base.astro:79`, `src/data/i18n.ts:93-96`
- **Evidence:**
  ```astro
  <Base lang="en" title="404">
  ```
  ```ts
  const path = Astro.url.pathname;
  const canonical = new URL(path, Astro.site);
  const otherPath = altPath ?? switchLangPath(path, other);
  ```
  ```astro
  <a class="lang-switch" href={otherPath} hreflang={other} lang={other} data-testid="lang-switch">
  ```
- **Why it matters:** `404.astro` passes no `altPath`, so `otherPath` becomes `/es/404…`. No `src/pages/es/404.astro` exists (I confirmed the file is missing). Every visitor who lands on an unknown URL sees an "Español" link that leads to another 404. The page also emits a canonical URL and `hreflang` alternates for an error page. `tests/quality.spec.ts:51-55` only checks the status and text, and `/404` is not in `tests/pages.ts`, so nothing catches this.
- **Suggested fix:** Pass `altPath="/es/"` from `404.astro`. Add a `noindex` prop to `Base` that suppresses canonical and alternates, and set it on the 404 page. Add a test that follows the 404 page's `lang-switch` link and expects a 200.

### R-04: The link checker only covers `<a href>`, so missing images, icons and the manifest go undetected
- **Severity:** Medium · **Category:** test quality
- **Location:** `tests/quality.spec.ts:24-34`
- **Evidence:**
  ```ts
  const hrefs = await page.locator('a[href]').evaluateAll((as) => as.map((a) => (a as HTMLAnchorElement).href));
  ```
- **Why it matters:** The site references many assets that are not anchors: `/favicon.svg`, `/favicon-32.png`, `/apple-touch-icon.png`, `/site.webmanifest` (`src/layouts/Base.astro:49-52`), `/og-image.png` (`Base.astro:59`), the three `/img/collab/*.webp` screenshots (`src/data/profile.ts:311,325,338`), and the icons listed in the manifest (`public/site.webmanifest:6,11,16`). The brand assets were reorganized recently (`brand/` is deleted in the working tree), so a missing file is a realistic regression. The README says the suite checks that "all internal links return 200", but it does not check these.
- **Suggested fix:** Also collect `link[href]`, `img[src]`, `meta[property="og:image"]` and `meta[name="twitter:image"]`, keep the same-origin ones, and request each one. Add one test that parses `site.webmanifest` and fetches every `icons[].src`.

### R-05: The committed CV PDFs are never checked against current data
- **Severity:** Medium · **Category:** test quality
- **Location:** `tests/cv.spec.ts:50-57`, `tests/home.spec.ts:27-37`, `README.md:42`
- **Evidence:**
  ```ts
  const pdf = await page.pdf({ format: 'Letter', printBackground: true, preferCSSPageSize: true });
  const pages = pdf.toString('latin1').match(/\/Type\s*\/Page[^s]/g) ?? [];
  expect(pages.length).toBeLessThanOrEqual(2);
  ```
  ```ts
  expect((await res.body()).subarray(0, 5).toString()).toBe('%PDF-');
  ```
- **Why it matters:** Users download the committed files `public/cv/*.pdf`, which come from a manual `npm run cv`. The two-page test checks a PDF it prints itself from the HTML, and the download test only checks the magic bytes. If someone edits `profile.ts` and forgets to run `npm run cv`, CI stays green while recruiters download a stale CV. For example, the Coda project added in `9db48f3` would be missing. The README says "`tests/cv.spec.ts` keeps both to two pages", which is not true of the committed files.
- **Suggested fix:** In the download test, also count pages in the downloaded body with the same regex, and check for one current fact such as the latest role or the Coda project name. If the text is compressed in the PDF, use the PDF outline (`outline: true` is set in `scripts/build-cv.mjs:30`). Another option is a CI step that runs `npm run cv` and fails on `git diff --exit-code public/cv/`.

### R-06: CI can cancel a Pages deploy mid-run and gives pull requests Pages write permission
- **Severity:** Medium · **Category:** CI
- **Location:** `.github/workflows/ci.yml:9-16`, `.github/workflows/ci.yml:39-41`
- **Evidence:**
  ```yaml
  permissions:
    contents: read
    pages: write
    id-token: write

  concurrency:
    group: pages-${{ github.ref }}
    cancel-in-progress: true
  ```
  ```yaml
      - uses: actions/upload-pages-artifact@v3
        with:
          path: dist/
  ```
- **Why it matters:** With `cancel-in-progress: true`, a second push to `main` cancels the run that is already deploying. GitHub's Pages starter workflows use `cancel-in-progress: false` for this reason, because a cancelled `deploy-pages` can leave a deployment half-finished. The `pages: write` and `id-token: write` permissions are set for the whole workflow, so the `test` job on every pull request also gets them, even though only `deploy` needs them. The Pages artifact is also uploaded on pull-request runs, where it is never used.
- **Suggested fix:** Set `permissions: contents: read` at the top level and move `pages: write` and `id-token: write` into the `deploy` job. Either keep `cancel-in-progress: true` for the `test` job only, or set it to `false` for deploys. Add `if: github.ref == 'refs/heads/main' && github.event_name != 'pull_request'` to the `upload-pages-artifact` step.

### R-08: Local `npm test` reuses the dev server, so local runs may not test the production build
- **Severity:** Low · **Category:** test quality
- **Location:** `playwright.config.ts:3`, `playwright.config.ts:19-24`, `README.md:31-33`
- **Evidence:**
  ```ts
  const PORT = 4321;
  ...
    // Tests run against the production build, not the dev server.
    webServer: {
      command: `npx astro preview --port ${PORT} --ignore-lock`,
      url: `http://localhost:${PORT}`,
      reuseExistingServer: !process.env.CI,
  ```
- **Why it matters:** `npm run dev` also serves on 4321 (`README.md:31`). If the dev server is running, a local `npm test` reuses it and tests the dev server, where drafts are visible (`src/data/blog.ts:11`), so the comment in the config is wrong locally. The webServer does not build first either, so running `npm test` without `npm run build` serves a stale or missing `dist/`. CI is not affected.
- **Suggested fix:** Use a dedicated port for the test server, for example 4322 as in `scripts/build-cv.mjs`. Either document that `npm run build` must run first, or make the webServer command `npm run build && npx astro preview …` when not in CI.

### R-09: `build-cv.mjs` does not close the browser on failure and hides server errors
- **Severity:** Low · **Category:** readability
- **Location:** `scripts/build-cv.mjs:13`, `scripts/build-cv.mjs:24-38`
- **Evidence:**
  ```js
  const server = spawn('npx', ['astro', 'preview', '--port', String(PORT), '--ignore-lock'], { stdio: 'ignore' });
  ...
    const browser = await chromium.launch();
    ...
    await browser.close();
  } finally {
    server.kill();
  }
  ```
- **Why it matters:** If `page.goto` or `page.pdf` throws, `browser.close()` is skipped and only the server is killed, which can leave a Chromium process running. Because the preview server's output goes to `stdio: 'ignore'`, a startup failure such as a port conflict or a missing `dist/` only shows up after about 15 s as a generic "did not start" error. The script also never checks that the page count is ≤ 2 before writing the committed PDF.
- **Suggested fix:** Declare `let browser` outside the `try` block and call `await browser?.close()` in `finally`. Use `stdio: ['ignore', 'ignore', 'inherit']` so server errors are visible. Optionally reuse the page-count check from `tests/cv.spec.ts:55` and fail when the result exceeds two pages.

## Test suite assessment
- **Strengths:**
  - Every route in `tests/pages.ts` gets an axe WCAG 2.1 A/AA scan, SEO and hreflang assertions, a link check and an anchor check (`tests/quality.spec.ts:5-49`).
  - The CV download test checks the status, content type and `%PDF-` magic bytes, not just that the link exists (`tests/home.spec.ts:27-37`).
  - The CV rules (no freelance work, no non-certificate education, `noindex`, two pages) are written as explicit tests (`tests/cv.spec.ts`).
  - The suite runs on desktop and mobile projects with `forbidOnly` and one retry in CI (`playwright.config.ts:8-9,15-18`).
  - Locators are mostly role- and test-id based, and there are no fixed sleeps anywhere.
- **Gaps:**
  - The fonts (R-01), non-anchor assets (R-04), the committed CV PDFs (R-05) and the Collaborations section (R-03) are not covered.
  - The 404 page's own links are untested (R-02).
  - The `hreflang` test only checks the alternate for the page's own language. The other-language alternate and `x-default` are counted but their `href` is never checked (`tests/quality.spec.ts:19-21`).
  - The RSS test checks that `<item>` and `<link>` exist but not that the links resolve (`tests/quality.spec.ts:57-65`).
  - Mobile navigation is skipped instead of tested (R-11).
- **Assertion quality:** `expect.soft` in the link and anchor loops still fails the test, and each failure is reported with the URL, which is good. `tests/home.spec.ts:8-10` uses a layout class (`.job`) where a role-based `listitem` inside the Experience region would be more robust. This is acceptable because the class name is used consistently.
- **Flakiness:** Low risk. The tests make no third-party network calls, since only same-origin links are fetched. Link requests run one after another, which is slower but deterministic.
- **Maintainability:** The page and pair lists are hand-maintained and duplicated (R-10).

## Needs verification
- **Spanish month abbreviations in `formatMonth`** (`src/data/i18n.ts:98-107`). The code assumes `es-CO` short months look like `"sept de 2026"`. Some ICU versions add a trailing period (`"sept. de 2026"`), which would render "Sept. 2026" and break the intended format. To confirm, run `new Date(Date.UTC(2026,8,1)).toLocaleDateString('es-CO',{month:'short',year:'numeric',timeZone:'UTC'})` on the Node version used in CI (22). No test asserts formatted dates.
- **Public binaries.** I could not list `public/` without Glob. `public/og-image.png` and `public/favicon.svg` exist. I could not confirm `favicon-32.png`, `apple-touch-icon.png`, `icon-192.png`, `icon-512.png`, `icon-512-maskable.png`, `img/collab/*.webp` or `cv/*.pdf`. Run `ls` on those paths or add the asset check from R-04.
- **Page-count regex** (`tests/cv.spec.ts:55`). `/\/Type\s*\/Page[^s]/` assumes uncompressed page objects in Chromium's PDF output. If Chromium ever writes page dictionaries into compressed object streams, the count would be 0 and the test would always pass. Print a CV that is deliberately three pages long and confirm the test fails.
- **Unlisted files.** Without Glob, any file under `src/` or `scripts/` that nothing imports and the README does not mention was not reviewed. Run `git ls-files src scripts tests .github` to confirm the list.

## Strengths
- There is a single source of truth for bilingual content. `src/data/profile.ts` keeps EN and ES side by side, and `UIKey` (`src/data/i18n.ts:80-84`) makes a missing `es` key a type error.
- The site ships no JS. Icons are inlined at build time with `aria-hidden` and `focusable="false"` (`src/components/Icon.astro:17-22`), and the decorative logos default to `aria-hidden` (`src/components/Logo.astro:23-25`).
- The CV is generated from the same data, keeps freelance work out by design with a clear comment (`src/components/CV.astro:48-52`), and the tests enforce that rule.
- Deploys are gated on tests (`.github/workflows/ci.yml:43-46`) and run against the production build, with the reports uploaded even when tests fail (`ci.yml:33-38`).
- The language-switch and canonical logic is centralized and small (`src/data/i18n.ts:87-96`, `src/layouts/Base.astro:21-25`), and blog posts override it explicitly with `altPath` (`src/components/BlogPost.astro:15`).
